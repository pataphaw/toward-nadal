# 视频精选 v1.0.0 重设计验证

## 文档定位
本文档记录 `05-video-selection` 从 CV-heavy 方案升级到 `CV 候选生成 + 本地视觉模型 rerank` 方案的依据。

它回答的问题是：
- 为什么旧 selection 主线不应继续通过 CV 规则调参推进。
- 新版 `v1.0.0` 为什么要升主版本。
- 新方案如何对应 CV 与本地视觉模型的能力边界。

## 验证对象
本次验证对应：
- 归档版本：[视频精选方案历史（v0.4.0）](../solution/05-video-selection/history/v0.4.0.md)
- 当前方案：[视频精选架构（Current）](../solution/05-video-selection/current.md)

## 背景
旧方案持续沿着 `OpenCV + NumPy + 规则特征` 方向调优，目标是自动选出优质、覆盖范围广、适合后续分析的视频片段。

但最近验证已经显示：
- 规则层能跑通 selection 流程。
- 规则层能生成一定质量的候选。
- 规则层仍不能稳定区分打球中动作与休息 / 捡球 / 回位中的高运动。
- 规则层仍不能可靠判断候选是否完整、是否值得复盘、是否覆盖关键技术动作。

## 关键观察
### 1. 旧方案的失败不是单个阈值问题
`img_3026` 的跨视频复核显示，旧方案已经有 `in-play gate` 与 `transit-motion-risk`，但仍然把休息 / 捡球段选入最终结果。

这说明问题不只是：
- 某个阈值偏高或偏低。

而是：
- CV 规则缺少稳定的候选级语义理解能力。

### 2. Selection 的真实目标超出纯 CV 能力边界
本项目需要的不是“运动最强的片段”，而是：
- 真正在打球。
- rally 尽量完整。
- 覆盖正手、反手、发球或其他关注动作。
- 同时包含亮点样本和问题样本。
- 能作为后续技术分析的代表样本。

这些判断需要视觉语义理解，不能长期依赖运动密度、站位和手写启发式规则伪装完成。

### 3. CV 仍然有明确价值
CV 不应被移除。

它仍然适合：
- 视频质量过滤。
- 高召回候选生成。
- 运动证据提取。
- 候选窗口定位。
- 候选池压缩。

这些能力能显著降低本地视觉模型的调用成本，并保持结果可追溯。

### 4. 本地视觉模型应成为最终 rerank 层
当前 Mac 本地环境适合让视觉模型处理短候选，而不是处理长视频。

因此更合理的职责划分是：
- CV 把长视频压缩成少量候选。
- 本地视觉模型判断候选是否真在打球、是否完整、是否值得复盘。
- selection 只负责覆盖约束、去重、排序和不确定性暴露。

## 方案影响
本次结论触发 `05-video-selection` 主版本升级：
- 旧主线归档为 `v0.4.0-cv-heavy-rally-interval-export`。
- 当前版本升级为 `v1.0.0-cv-candidates-local-vlm-rerank`。

新版方案不再把旧 CV 调优逻辑作为设计基础。

后续实现应避免：
- 继续堆叠休息段排除规则。
- 继续用站位启发式强判正手 / 反手 / 发球。
- 继续让 CV 分数承担“是否值得复盘”的语义判断。

后续实现应优先建设：
- `cv_candidate_builder`
- `model_input_builder`
- `vision_reranker`
- `coverage_selector`

## 结论
继续调优 CV-only selection 的边际收益已经明显下降。

正确方向不是放弃 CV，而是降低 CV 的职责：
- CV 做高召回、低成本、可解释的候选生成。
- 本地视觉模型做候选级语义判断与 rerank。

这就是 `v1.0.0` 的设计基础。
