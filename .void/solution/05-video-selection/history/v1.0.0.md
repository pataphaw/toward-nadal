## 版本定位
`v1.0.0` 确立了新的主方向：
- `CV` 只做高召回候选生成与证据提取。
- 本地视觉模型负责候选级语义判断。
- selection 负责覆盖约束、去重、排序和不确定性暴露。

它替代了旧的 CV-heavy 规则精选器。

## 已明确的设计
该版本已经明确：
- 不再让 `CV` 承担最终语义裁判。
- 不再继续堆叠休息 / 捡球排除规则。
- 不再用站位启发式强判正手、反手和发球。
- 采用 `cv_candidate`、`model_judgement`、`reranked_selection` 三类核心对象。
- 本地视觉模型只处理短候选，不处理长视频全量扫描。

## 暴露的问题
该版本仍不足以直接交给工程实现：
- 没有锁定 v1 第一版使用的本地视觉模型运行时。
- 没有完整定义 `selection_package`、`cv_candidate`、`model_input_package`、`model_judgement` 的字段类型与枚举。
- 没有规定模型输入落盘目录、关键帧命名、缓存复用和模型响应记录方式。
- 没有固定 prompt、JSON schema、重试策略和非法输出处理。
- 没有给出可直接编码的 rerank 权重、阈值和覆盖槽位规则。
- 与 06 analysis 的 `focus_window` 输入契约存在字段不匹配。

## 被替代原因
`v1.0.0` 是方向正确的架构草案，但不是实现规格。

后续版本需要把它补齐为：
- 可编码的数据契约。
- 固定的第一版模型适配路径。
- 明确的下游兼容策略。
- 可验证的测试场景。
