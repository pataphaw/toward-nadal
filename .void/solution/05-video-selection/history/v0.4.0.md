## 版本定位
`v0.4.0` 是旧 selection 主线的终点。

它仍然以 `OpenCV + NumPy + 规则特征` 为主，尝试通过持续增强启发式逻辑来完成：
- `in-play` 判断
- 休息 / 捡球段排除
- `focus_window` 定位
- `selected_clip_window` 导出
- 正手 / 反手 / 发球粗覆盖
- 亮点 / 问题样本粗排序

## 已解决的问题
该版本证明了 CV-heavy 方案具备一定价值：
- 可以把 04 输出的 `point_clips` 转换成更小的分析候选。
- 可以用运动密度、音频峰值和低阈值区间恢复更完整的候选窗口。
- 可以输出 `candidate_pool`、`selected_clips`、`coverage_report` 和 `review_queue`。
- 可以在部分视频上减少明显无效片段进入最终精选。

## 暴露的问题
该版本在跨视频复核中暴露出结构性上限：
- `in-play gate` 仍会把休息 / 捡球 / 回位中的高运动误判为打球。
- `selected_clip_window` 仍可能截断 rally 尾部。
- 正手 / 反手 / 发球等语义标签主要来自弱启发式，不能稳定承担硬覆盖判断。
- “是否值得复盘”本质上是语义判断，无法靠运动强度和规则分数稳定表达。

## 被替代原因
该版本不是因为局部实现失败而被替代，而是因为任务目标超过了纯 CV 规则的稳定能力边界。

继续沿着旧主线调参会导致：
- 规则数量不断增加。
- 单视频适配倾向增强。
- 跨视频泛化仍不稳定。
- 语义判断被伪装成可解释分数。

因此后续主线升级为：
- `CV` 负责高召回候选生成。
- 本地视觉模型负责语义判断与 rerank。
