# 视频精选方案历史（V1）

## 文档定位
本文档归档视频精选子域的首个可运行里程碑版本，便于后续回溯。

它对应的不是“最终可用形态”，而是第一次把 `05 selection` 真正跑通的版本。

相关文档：
- 当前方案：[视频精选架构（Current）](../current.md)
- 反馈验证：[2026-04-25-video-selection-img3076-rally-completeness](../../../validation/2026-04-25-video-selection-img3076-rally-completeness.md)

## 版本标识
归档版本为 `V1-highlight-window-export`。

## 该版本解决了什么
- 可以直接消费 04 输出的 `manifest.json + point_clips/`
- 可以用本地 `OpenCV + NumPy + ffmpeg` 生成 `candidate_pool`
- 可以对候选样本补充 `forehand / backhand / serve-like / baseline / midcourt / stationary / running / highlight / problem-example`
- 可以输出 `selection package`
- 可以把选中的窗口导出成实际视频片段

## 该版本的核心做法
- 选择对象从整段 `point clip` 升级为带 `focus_window` 的 `analysis candidate`
- 候选窗口分为三类：
  - `dense-cluster`
  - `opening-probe`
  - `wide-motion`
- 候选池不再是单纯总分截断，而是保留一定的类型多样性

## 该版本的关键限制
这个版本虽然已经能选出“精彩击球附近”的片段，但导出策略仍然有明显问题：
- `selected_clip` 直接使用 `focus_window` 导出
- 当 `focus_window` 只覆盖高密度击球段时，导出片段会在回合中间开始或结束
- 结果是：
  - 精彩击球本身往往被抓到了
  - 但回合完整性被破坏

这个问题在 `img_3076` 的真实抽查中被用户明确指出，因此该版本不再作为当前生效版本。

## 替代关系
`V1-highlight-window-export` 已被当前版本替代。

当前版本的核心修正是：
- `focus_window` 继续承担“精彩击球定位”
- 新增完整 rally 语义下的 `selected_clip_window`
- 导出视频从 `selected_clip_window` 而不是 `focus_window` 截取
