# 视频精选方案历史（v1.0.3）

## 版本
`v1.0.3-single-final-selected-clips`

## 背景
`v1.0.2` 已经恢复了可信的 non-empty selection，但仍然保留了一个产物语义问题：

- `selection_runs/` 下会保留多次实验 run，这是合理的。
- 但 `selected_clips/` 也按 run id 建立多个子目录，导致“最终结果目录”同时暴露多组互相竞争的结果。
- 不同 run 可能重复导出相同片段，使 `selected_clips/` 出现大量重复视频。

这会让下游难以判断哪个目录才是当前正式输入，也让“最终输出”失去单一语义。

## 本版核心修复
- `selection_runs/<selection_run_id>/` 继续保存多次运行的完整记录。
- `selected_clips/` 改为 run 级单一最终输出目录，不再按多个 `selection_run_id` 并列保留。
- 成功 selection 默认覆盖 `<run-dir>/selected_clips/`，只保留当前被 promotion 的一组视频切片。
- `selected_clips/manifest.json` 记录：
  - 当前结果来自哪个 `selection_run_id`
  - 导出数量
  - 每个导出视频的基础元数据
- `selection-package.json` 新增：
  - `selected_clips_result_role`
  - `promoted_selected_clips`
- 如果只是实验 run，不想覆盖最终结果，调用时可显式传 `--skip-promote-selected-clips`。
- CLI 参数优先级修复为“显式 CLI > config.toml > code default”，避免显式参数在值等于默认值时被 config 静默覆盖。

## 当前结论
这一版解决的是“最终输出目录语义”问题，而不是再改模型质量：

- `selection_runs/` 是审计记录。
- `selected_clips/` 是单一生效结果。
- 下游应消费 `selected_clips/`，并通过 `manifest.json` 追溯其来源 run。
