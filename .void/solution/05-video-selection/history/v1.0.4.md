# 视频精选方案历史（v1.0.4）

## 版本
`v1.0.4-local-vlm-serial-stability`

## 背景
`v1.0.3` 已经修正了最终输出目录语义，但本地模型调用仍有一类不符合预期的失败：

- `model_unavailable` 经常来自 `request_error:timed out`
- 这不是“模型不存在”，而是本地运行时控制不稳
- 结合现场现象，问题集中在两点：
  - 多次 selection run 可能并发争抢同一个 Ollama 实例
  - 新 run 启动前，旧模型任务可能仍残留在 `ollama ps`

## 本版核心修复
- 引入全局本地 VLM 锁，确保同一时间只有一个 selection run 进入模型判断阶段。
- 在实际请求前增加 `ollama ps` preflight：
  - 发现残留模型任务时，先尝试清理
  - 等待 Ollama 回到空闲状态
  - 若仍不空闲，则直接失败，不带脏状态继续跑
- 默认本地模型配置进一步降载：
  - `model = qwen2.5vl:3b`
  - `fallback_model = qwen2.5vl:3b`
  - `candidate_pool_size = 4`
  - `selected_size = 3`
  - `frames_per_candidate = 2`
  - `timeout_seconds = 180`
- CLI 参数优先级保持为 `CLI > config.toml > default`。

## 当前结论
这一版的重点不是提升语义判断质量，而是让“本地模型必须能稳定被调用”成为实现层硬约束：

- 不并发打模型
- 不带残留任务开跑
- 不默认切到更重的 `7b`
