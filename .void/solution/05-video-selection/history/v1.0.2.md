# 视频精选方案历史（v1.0.2）

## 版本
`v1.0.2-local-vlm-selection-recovery`

## 背景
`v1.0.1` 在新视频上暴露出两类实现级问题：

- `04 segment` 修复后，`05 selection` 不再是 `empty-point-clips`，但本地 VLM 经常超时。
- 即使显式传入更小的 `candidate_pool_size` 和 `frames_per_candidate`，实现层仍然偷偷扩大到至少 `12` 个候选、至少 `6` 帧，导致调参失效。
- 当模型只返回非法 JSON 时，代码会写入 `uncertain fallback judgement`，并继续产出看似成功的 `selected_clips`，形成伪成功。

## 本版核心修复
- `candidate_pool_size` 真实按输入参数生效，只做 `>=1` 的下界保护。
- `frames_per_candidate` 真实按输入参数生效，只做 `1..12` 的安全钳制。
- 默认运行参数收敛为已验证能跑通的主路径：
  - `candidate_pool_size = 4`
  - `selected_size = 3`
  - `frames_per_candidate = 2`
  - `model = qwen2.5vl:3b`
  - `fallback_model = qwen2.5vl:7b`
- Ollama 请求从依赖 transport-level JSON Schema，改为：
  - `format = json`
  - prompt 内显式写出目标字段、枚举和值域
- 模型原始响应在解析前先落盘，便于追查非法输出。
- 若整轮没有任何合法 `model_judgement`，输出必须是 `selection_status = model_unavailable`；不再允许 fallback judgement 驱动伪成功 selection。

## 当前结论
这一版的目标不是解决本地 VLM 的全部语义质量问题，而是先恢复“可信的非空 selection”：

- `selection` 结果必须建立在至少一个合法 `model_judgement` 上。
- `no_candidates` 与 `model_unavailable` 要被清晰区分。
- 参数调优必须真实影响运行时行为，而不是被实现层静默覆盖。
