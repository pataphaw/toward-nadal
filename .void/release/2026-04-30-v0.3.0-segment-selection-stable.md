# v0.3.0 阶段发布（Segment + Selection 稳定版）

## 阶段名称
`v0.3.0-segment-selection-stable`

## Release 强约束
- 一次 release 必须对应“一组版本化 solution 的集合”，不能只引用笼统的 `current`。
- release 文档必须给出结构化 `solution matrix`：`子域 -> 版本号 -> 固定文档链接 -> 是否纳入本次 release`。

## 已完成内容
- 视频切片子域进入阶段性稳定版本：`V1.1-segment-stable-beta`。
- 视频精选子域保持在可实现、可运行的主线版本：`v1.0.1-implementation-ready-local-vlm-rerank`。
- `validation -> versioned solution` 的强关联约束已落地到仓库协作规范。
- 已建立并补齐本阶段关键验证证据链，覆盖 `img_3132` 回合边界硬约束问题。

## 当前可用范围
- 04 切片可稳定输出 `point_clips`、`manifest` 与边界证据字段。
- 05 精选可基于切片结果执行候选生成、本地视觉模型判定与结果筛选。
- 端到端可形成“切片 -> 精选 -> 后续分析输入”的可用链路。

## 已知限制
- 片段边界质量整体明显提升，但仍存在少量“结尾提前截断”残余样本。
- 当前阶段不继续优化 segment 规则，先冻结以保障跨子域并行推进。
- 04 仍以 `point-first` 为主，完整 `segment clip` 时间轴与 `break` 片段尚未进入当前交付范围。
- `selection` 当前仍以 `boundary_status=confirmed` 作为硬门槛；在弱音频/弱静音边界素材中，可能因锚点缺失而过滤掉部分短回合样本，需在后续回归中重点观察覆盖率变化。
- tail-trim 参数在当前实现中已标记为 ignored（并写入 manifest policy），但 CLI 参数仍保留，外部脚本若未读取策略字段可能误判参数有效性。

## 后续阶段入口
- 在不变更当前稳定主线的前提下，推进 06/07 子域实现与联调。
- 下一轮若重启 04 边界优化，先归档当前方案版本，再提交对应版本化 validation。
- 下一轮边界治理优先考虑：
  1. 弱边界素材下的 `confirmed` 过滤覆盖率回归统计。
  2. tail-trim 相关 CLI 参数的 `deprecated/ignored` 明示或移除。
